**Slide 4: RAG 기술 개념**
```
Traditional LLM:
  User Query → LLM → Response (학습 데이터 기반)

RAG:
  User Query → Retriever (문서 검색) → Relevant Docs
                ↓
            Augment (문서 + Query)
                ↓
              LLM → Response (문서 기반 답변)
```

**Slide 5: RAG의 핵심 장점**
1. ✅ **최신 정보 반영**: 문서만 업데이트하면 OK
2. ✅ **Hallucination 감소**: 문서 기반 답변으로 정확도 ↑
3. ✅ **도메인 특화**: 회사 내부 문서 활용
4. ✅ **비용 효율**: Fine-tuning 불필요

### Part 2: 시스템 아키텍처 (10분, Slide 6-12)

**Slide 6: ChatPro 아키텍처 전체도**
```
Frontend (Svelte)
    ↓
Backend API (FastAPI)
    ↓
┌─────────────────────────────┐
│   RAG Pipeline              │
│ 1. Query → Embedding        │
│ 2. Vector Search (Milvus)   │
│ 3. Context Retrieval        │
│ 4. LLM Prompting (Qwen2)    │
│ 5. Response Streaming       │
└─────────────────────────────┘
    ↓
Vector DB (Milvus) ← Document Processing
                     (Docling, Chunking)
```

**Slide 7: 문서 처리 파이프라인**
1. **문서 입력**: PDF, DOCX, PPTX, XLSX 등
2. **파싱**: Docling (구조 유지) 또는 Python 라이브러리
3. **청킹**: RecursiveCharacterTextSplitter (500 tokens)
4. **임베딩**: KURE-v1 (한국어 최적화)
5. **저장**: Milvus Vector DB

**Slide 8: 벡터 DB 선정 - Milvus**
| 특징 | Milvus | Pinecone | Weaviate |
|------|--------|----------|----------|
| 온프레미스 | ✅ | ❌ | ✅ |
| 한국어 지원 | ✅ | ✅ | ✅ |
| 성능 | 우수 | 우수 | 보통 |
| 비용 | 무료 | 유료 | 무료 |
| **선택** | **채택** | 제외 | 제외 |

**Slide 9: 임베딩 모델 - KURE-v1**
- 개발: 서울대학교 AI연구원
- 특화: 한국어 의미 이해
- 성능: 영어 모델 대비 한국어 정확도 +25%
- 차원: 768차원
- **결과**: 한국어 질의 정확도 90% 이상

**Slide 10: LLM 선정 - Qwen2 1.5B**
- 온프레미스 배포 가능
- 성능: GPT-3.5 수준
- 추론 속도: GPU 사용 시 2초 이내
- 한국어 지원: 우수
- 비용: 무료 (오픈소스)

**Slide 11: Retrieval 전략**
1. **Hybrid Search**: Vector + Keyword
2. **Re-ranking**: Cross-encoder로 재정렬
3. **Top-K**: 상위 5개 문서 선택
4. **Context Window**: 최대 3,000 tokens

**Slide 12: 권한 관리 시스템**
- EDM(Enterprise Document Management) 연동
- 사용자별 문서 접근 권한 체크
- `maxObjtSharePolicyId` 기반 필터링
- **결과**: 권한 없는 문서는 검색 결과에서 제외

### Part 3: 구현 사례 - ChatPro (10분, Slide 13-18)

**Slide 13: ChatPro 주요 기능**
1. 자연어 질의응답
2. EDM 파일 검색 및 임베딩
3. 대화 히스토리 관리

5. 실시간 스트리밍 응답

**Slide 14: 사용자 워크플로우**
```
1. 사용자가 "프로젝트 제안서 내용 요약해줘" 입력
   ↓
2. 시스템이 EDM에서 "프로젝트" 키워드로 파일 검색
   ↓
3. 사용자가 파일 선택 (권한 체크)
   ↓
4. 선택한 파일 임베딩 (Milvus에 저장)
   ↓
5. 질문에 대한 관련 문서 검색
   ↓
6. LLM이 문서 기반 답변 생성
   ↓
7. 사용자에게 스트리밍 응답 제공
```

- **결과**: RAM 사용량 70% 감소 (8GB → 2.4GB)

  2. 벡터 검색 서비스 (Milvus 클러스터)
